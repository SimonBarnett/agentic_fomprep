# Planning Issues

 

MRP creates an issues plan based on the demand for purchased (Type R ) parts generated by open work orders, the work orders planned by MRP and other sources (e.g., sales orders for purchased parts). When the program is run using the By Demand Range option, work orders and issues are planned according to the demand range defined for each parent (Type P ) part. Details. 
 
## Note: 

 

An issues plan is only created when you run MRP in real mode. If you run the Issues Plan report after running an MRP simulation, it will display the results of the last real MRP run. 
 
## Opening Work Orders

 

Running MRP in real mode – using the runtime option Open Work Orders – opens work orders according to those planned by the program. However, if you have set the WorkOrdNum constant to 0 , or if no work order template was defined for a given part, MRP will plan work orders without actually opening them in the Work Orders form. 
 

New work orders are opened each time you run MRP; consequently, any work orders that were opened in a previous run but were not released are deleted. 
 
## Preparing a Work Plan

 

When running MRP in Open Work Orders mode, you can choose to produce a work plan for all the work orders it opens. Work planning takes into account each operation's production timing parameters, and optimizes the timing of operations within the constraints set by due dates. 
 

Alternatively, you can open an individual work plan for each opened work order by Direct Activation from the Work Orders form. 
 
## Note:

 

You can lock any open and released work order into its planned time by flagging the Freeze Planning column in the Prod. Data tab of the Work Orders form. This will prevent anyone from rescheduling the work order, though it may result in the work order losing its relevance (e.g., if the sales order for which it was opened is moved up beyond the tolerance value).
