# Internal Quote Training

- **Source:** `Internal Quote Training.docx`

Internal Quote Training 23/07/25

Overview and Fields to Use

2 facets - customer facing

not technical

not ambiguous

how long it would take

aim for the contact who raised it to understand the detail (doesn't need to be completely idiot proof)

technical details are recorded for internal purposes

Details - high level summary of what it's about

Type - usually SC request

but might be cust req, module (remember to add extra line for 20% annual maintenance, 3rd line for setup time)

quote for training - as much detail from customer about what they want to be covered

what they want to achieve from it.

support is using for investigation time for a service call.

CM can auth these ones

use SUP authoriser list in this case

Part to use is CONS-HR-MED which is consultancy time

description should be detailed

Quote Body

Background - what's the business case?

why do they want the quote?

Cust Requirement - what do they want us to do?

Pre-conditions - assumptions about data for the change to work

business process

Post condition - what should happen after

Development- customer version of the spec

use bullet points

Validation - checks on new data?

Supporting Document - e.g. Ceres RFQ

Time, Spec and Checks

Tech spec for developer goes in Quote Development Design Info

doesn't copy to the sales order

where to look, which procedure, which step, what lines etc.

need to be looking at the customers system when creating the quote

prep quote time - time to write the quote

internal qty - how long it would take Medatech to do the work

think about an average developer with experience

and consider time for developer to read and understand

should include testing etc.

if testing time is going to take a long time, at bold note in dev design info how long added to quote for testing

this gets added to internal qty

total qty is double internal qty + internal prep time

this gives breathing room for unexpected things, communication, testing, slow developers!

Bank of hours quotes set internal qty to external qty

(for calling off)

print off quote and check before sending for auth

Making Changes

new version- save version and set to not authorised

then change to draft

make it clear to authorisers what has changed and whether significant

could add to design info so customer doesn't see esp. if changing the qty
