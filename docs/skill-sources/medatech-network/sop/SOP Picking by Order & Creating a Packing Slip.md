SOP: Picking by Order & Creating a Packing Slip* 
Customer:   Company Inc. 
Assigned to: Dept./Position 
Aim 
 To pick inventory from storage bins in zones flagged as loading decks, from the 
creation of a wave of pick tasks for designated orders, to the task reporting, and 
to the creation of the relevant inventory document (Packing Slip). 
Note: If you use the order work area to select order items for the pick wave, see 
SOP: Picking by Order Work Area instead. 
Working Assumptions 
 The PIK task type has been defined so that all completed PIK tasks result in the 
creation of a packing slip (in the Warehouse Task Types form). 
 For each customer, the target document to be created upon completion of a "Pick 
Up for Orders" (PIK) task has been defined as a packing slip (in the Target Doc 
per Task Type/Cust. form). Likewise, the target document to be created upon 
completion of a "Ship Packed Crates" (SHP) task has been defined as a 
warehouse transfer or shipping document (see SOP: Setting Up Warehouse 
Management (WMS Pick)). 
 A status has been defined for documents that are prepared automatically upon 
completion of a PIK task (in the Document Types per Task Type form, a sub-
level of Warehouse Task Types). Otherwise, the default initial status is assigned 
to these documents. 
 There is sufficient inventory in at least one warehouse bin in the relevant storage 
zone. 
 All other necessary setups have been performed for the module (see SOP: 
Setting Up Warehouse Management (WMS Pick). 
Procedure 
Stage I: Creating a Pick Wave 
Aim: To open PIK tasks for specific orders. 
1. Run the Create Pick Wave (by Order) program. 
2. In the first input screen, fill in the following parameters:

 Task Split Method – Determine how the pick wave will be split into tasks. 
Select 001 (Per Order) to create a separate task for each order. For palleted 
goods, a separate task will be opened for each order and pallet. 
 Pick Strategy – Specify the strategy that will determine the pick order of the 
inventory for tasks opened by this wave. 
 Warehouse – Choose the warehouse from which inventory will be picked. 
 Assigned to – Designate the employee who will be responsible for each task 
created by this wave. 
 Task Date – Designate the date on which tasks generated by this wave will be 
opened. Today's date is filled in automatically but can be revised. 
 Priority – Indicate the relative importance to be assigned to warehouse tasks 
created by this wave. 
 Select the desired Retrieval Type. For example, specify 1 to retrieve by 
multiple criteria. 
 Indicate a Shipping Pallet, where necessary. 
 Indicate the Max No. of Lines that can be included in each picking task 
created by this wave. This value affects the number of tasks created by the 
wave. 
 Indicate the Maximum Volume of items that can be included in each picking 
task created by this wave  
 Make sure the Auto Release column is flagged, and the Auto Flagging and 
No Auto Flag Check columns are not flagged. 
 If you also want to generate replenishment tasks for the velocity A (fast) bins of 
the inventory to be picked, flag this wave for Hot Replenishent. 
Note: A detailed explanation of this subject can be found in the standard 
operating procedure ("SOP") on Setting Up Hot Replenishment. 
3. In the next input screen, fill in the following details: 
 From Zone/Main Zone – Specify the storage zone (or main zone) from which 
inventory will be picked. 
 From Velocity – To pick inventory only from those bins with a specific part 
velocity, designate the velocity in question. Alternatively, leave this column 
blank to pick inventory from bins with different velocities. 
Tip: Use operators (e.g., greater than or less than) to specify more than one 
part velocity. 
 If you want the wave to include only those orders that are linked to the storage 
zones in this wave, regardless of the designated retrieval type, flag the Incl. 
Orders in Zone column. 
 If sufficient goods are not available for one or more of the parts to be picked, a 
message is displayed alerting you of this, with a link to a report listing missing 
inventory for items included in the wave. 
Results 
 Picking (PIK) tasks have been opened with the "Execute" status. 
 Order items assigned the same Kit Number will be included in the PIK task only 
if sufficient inventory exists to fill all lines for that kit.

 Items linked to work orders containing a value in the Days Until Expirat'n, 
Quality Code or Allowed Inv Age-Mos. columns will be restricted to inventory 
available for picking that meet the work order criteria (expiration date of the lot, 
quality code or date code, respectively). 
Stage II: Manually Reporting to a PIK Task 
Aim: To report performance of a PIK task. 
Note: This stage applies to warehouse personnel who do not use mobile devices for 
reporting. 
1. Enter the Warehouse Tasks form. 
2. Retrieve the task assigned to you with the "Execute" Status. 
3. If necessary, you can print the task by selecting Print Warehouse Tasks from 
the list of Direct Activations. 
4. Enter the Warehouse Task Items sub-level form. 
5. For each part being picked, indicate the Actual Qty being picked. 
6. Make sure that the source warehouse and bins specified in the From 
Warehouse and From Bin columns are those that were actually used for picking. 
Modify as needed. 
7. In the Packing Crate Code column, indicate the type of crate or pallet being 
used to stack goods in the packing area. 
8. For each line, record the Label Number that is affixed to the designated crate. 
This value will be linked to the crate number assigned by Priority at a later stage. 
9. In the Document Number column, indicate how task items should be divided into 
crates when they are packed by specifying a different number for each crate. For 
example, if the first three items should be packed in the same crate, and the next 
two items should be packed separately in a second crate, specify 1 for the first 
three items and 2 for the next two items. 
10. If you wish to add the items in this task items to an existing packing slip rather 
than opening a new one, return to the upper-level form and indicate the number 
of the desired packing slip in the Add to Pack Slip column. 
11. In the upper-level form, change the task Status to "Fully Reported". 
Result 
 The picked quantity has been reported, but inventory balances have not yet been 
updated in the system. 
Stage III: Preparing Packing Slips 
Aim: To update inventory balances in the system, as a result of the task reported by 
warehouse personnel. 
Note: This stage applies to warehouse personnel who do not use mobile devices to 
prepare inventory documents. 
1. Enter the Warehouse Tasks form. 
2. Retrieve the task assigned to you with the "Fully Reported" Status. 
3. To create a packing slip, select Prepare Documents from the list of Direct 
Activations.

Note: The packing slip will be finalized if a final status was defined for inventory 
documents prepared upon completion of a PIK task (in the Document Types per 
Task Type sub-level of the Warehouse Task Types form). Otherwise, see the 
relevant standard operating procedure for further instructions on handling this 
document. 
Results 
 Inventory balances have been updated in the system, and reported quantities are 
recorded as transferred from the source bin to the target bin. 
 A packing slip has been created, or, if you chose to add task items to an existing 
slip, the latter is updated with items from the task in question. 
Process Summary 
As a result of the reported PIK tasks, inventory has been picked and transferred to a 
target bin based on system recommendations and actual task reports. 
To prepare the picked goods for shipping, see the SOP for Reporting to Shipping 
(SHP) Tasks.
