# SOP Putaway PUT by Documents Tasks

- **Source:** `SOP Putaway PUT by Documents Tasks.pdf`

Cat.No. LB110483 1 Ver.1 – Aug. 7,’11 
 
SOP: Putaway (PUT) by Document Tasks* 
Customer:   Company Inc. 
Assigned to: Dept./Position 
Aim 
 To put away inventory that was received into bins at the unloading deck. This 
process begins with the creation of a wave of putaway tasks for a designated 
inventory document, continues with task reporting, and ends with the creation of 
the relevant inventory document (Warehouse Transfer). 
The system's recommendations for putaway tasks created by this wave refer to parts 
that were received to the unloading deck by means of a final inventory document 
such as a GRV or warehouse transfer. 
Note: To put away inventory that was received via multiple documents, run the 
Create Put Wave (by Inventory) program (see the SOP for Putaway (PUT) By 
Inventory Tasks). 
Working Assumptions 
 The necessary setups have been performed for the WMS module (see the 
relevant standard operating procedure). 
 A status has been defined for documents that are prepared automatically upon 
completion of the task (in the Document Types per Task Type form, a sub-level 
of Warehouse Task Types). Otherwise, the default initial status is assigned to 
these documents. 
 A final inventory document (e.g., a GRV) has been recorded, documenting the 
receipt of inventory to a storage zone flagged as an Unloading Deck. 
Procedure 
Stage I: Creating a Put by Document Wave 
Aim: To open a PUT task, with which to perform putaway of items in a specific 
inventory document. 
1. Run the Create Put Wave (by Document) program. 
Note: The program takes into account only those parts that are located in a 
storage zone flagged as an Unloading Deck. 
2. In the first input screen, choose the warehouse in which inventory will be put 
away. 
3. In the next input screen, fill in the following details: 
                                                 
* Standard Operating Procedures should be used as guidelines for customers (and their consultants) to 
develop their own operating procedures. As you will note, the following procedures are very specific 
and customers are strongly advised not to use them without prior testing to make sure that they fit their 
own requirements and work practices.

 To Zone/Main Zone – Specify the storage zone (or main zone) in which 
inventory will be put away. 
 Store at Velocity – To put away inventory only in those bins with a specific 
part velocity, designate the velocity in question.  
Note: If you do not specify a velocity, and no velocity restrictions apply based 
on the part's put strategy, bins will be recommended for putaway irrespective of 
their velocity. 
 Task Date – Designate the date on which tasks generated by this wave will be 
opened. Today's date is filled in automatically but can be revised. 
 Priority – Indicate the relative importance to be assigned to warehouse tasks 
created by this wave. 
 To restrict the number of line items that can be included in each task created 
by this wave, specify the Max No. of Lines. 
 Indicate a From Document Date and To Document Date. The specified range 
of dates determines which receiving documents are retrieved for inclusion in 
the wave (in the form that opens next). 
 Make sure the Auto Release column is flagged. 
4. The GRVs/Warehouse Transfers form (Dual-currency users: 
GRVs/Transfers/Bonded Releases) opens. Select a single final document for 
inclusion in this wave. After ensuring that only the desired document appears, exit 
the form. 
5. The Flag GRV/Transf Items form (Dual-currency users: Flag 
GRV/Transf/Bonded Items) opens, displaying the items recorded in the selected 
receiving document. For each item, do one of the following: 
 To include the entire inventory balance in this wave, flag the Select column. 
 To include a part of this balance, specify the quantity to be put away in the 
Move Qty column. 
6. Exit the form to finish creating the put wave. 
7. If there is insufficient room for all goods to be put away, a message is displayed 
alerting you of this. Run the Wave Summary report and select Errors Only to 
view a list of all inventory left to put away. 
Result 
 
Putaway (PUT) tasks have been opened with the "Execute" status. 
Stage II: Manually Reporting to a PUT Task 
Aim: To report performance of a PUT task. 
Note: This stage is relevant for warehouse personnel who do not use mobile devices 
for reporting. 
1. Enter the Warehouse Tasks form. 
2. Retrieve the task assigned to you with the "Execute" Status. 
3. If necessary, you can print the task by selecting Print Warehouse Tasks from 
the list of Direct Activations. 
4. Enter the Warehouse Task Items sub-level form. 
5. For each part, indicate the Actual Qty being put away.

6. Make sure that the target warehouse and bins specified in the To Warehouse 
and To Bin columns are those that were actually used for the task. 
7. In the upper-level form, change the task Status to "Fully Reported". 
Result 
 
The transferred quantity has been reported, but inventory balances have not yet 
been updated in the system. 
Stage III: Preparing Inventory Documents 
Aim: To update inventory balances in the system, as a result of the task reported by 
warehouse personnel. 
Note: This stage is relevant for warehouse personnel who do not use mobile devices 
to prepare inventory documents. 
1. Enter the Warehouse Tasks form. 
2. Retrieve the task assigned to you with the "Fully Reported" Status. 
3. To create a warehouse transfer document, select Prepare Documents from the 
list of Direct Activations. 
Note: The transfer document will be finalized if a final status was defined for 
inventory documents prepared upon completion of a PUT task (in the Document 
Types per Task Type sub-level of the Warehouse Task Types form). Otherwise, see 
the relevant standard operating procedure for further instructions on handling this 
document. 
Result 
 
Inventory balances have been updated in the system, and a warehouse transfer 
document has been created, recording the transfer of goods from the specified 
source bin(s) to the target bin(s). 
Process Summary 
As a result of the reported PUT tasks, inventory has been put away in target bins on 
the basis of system recommendations and actual task reports.
