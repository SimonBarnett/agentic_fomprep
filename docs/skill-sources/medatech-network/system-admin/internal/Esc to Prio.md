Esc to Prio

We should only be raising bugs to Priority - i.e. issues seen in multiple systems and on the latest version

If it doesn’t repeat in the latest version, we are asking Priority if they have a back port. If the version (including points) is more than 3 versions old and they don’t have a back port, we need to ask customer to upgrade

If the version is less than 3 old and they don’t’ have a back port, we wait 6 months for the fix. After which, we need to cut our losses.

If it is a bug in the latest version and they agree to fix, we ask if there is a time frame, or a version we expect the fix in.

then we close call and add to future fixes

We tell customer it’s added to Priority’s dev backlog and there is no ETA. We will update if there is news

Queries - lets expect an answer within 3 months - if longer, check with CM maybe we need to take a different tact.

Everything needs to be reviewed by Gemma before raising. If GL not available, Cherry instead. GL will check when available so it’s noted everything raised and we can avoid duplicates.

This is so we can make sure all info is there when raising, we can avoid raising duplicate calls (or link calls if they are for different customers)

For specific customer issues we should aim for 6 months to fix. These can’t be added to future fixes. Similar to above, check with CM if gone over 6 months, we should review what we know.

We will add a “date raised to Priority” field.
