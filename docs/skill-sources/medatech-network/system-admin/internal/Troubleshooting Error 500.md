# Troubleshooting Error 500

- **Source:** `Troubleshooting Error 500.docx`

Troubleshooting Error 500

Obvious things to try first

Happens to one user

Restart PC

Reinstall priority web

Run Google Chrome as Administrator

Happens to all users

Reboot server(s)

Reinstall app server

Check server space

Check if any work is being done on the system

Check for “illegal” records (e.g. special character, blank mandatory fields)

Questions Priority ask

When raising this error to Priority, they will ask a list of questions. Try to answer as many as you can before raising it with them.

Does the customer have individual developments related?

In the Windows Interface, perform the same step that causes the error to appear and see which error message appears? (also try in rich on the IIS server)

Set up the web interface to work in debug mode according to instructions here to receive a more detailed message and attach all the detailed message.

Does the message repeat for all users? In all workstations?

Is there a specific action that causes the error to repeat? If so, please provide more information on the specific process that causes it to appear.

Are there errors in the server.log or wcf.log log files during the crash?

These files can be found in the Priority\log installation folder on the server.

WCF files are saved in the location defined by your IT personnel.

Please check whether relevant events occurred in the event viewer from when this issue first appeared.

Please attach a link to access your system, including a username and password so that we can check it on our end.

Please approve a charge in the event that this will require a programmer check (if you are working with an up-to-date version, there will be no charge if the error is found to be related to the standard Priority package).
