# Priority Template

- **Source:** `Priority Template.docx`

Customer:

The customer the service call is for

Error/Screenshot/Brief Description:

If there is an error message, include it here.

Otherwise, a screenshot or a sentence to summarise the issue

About Priority:

The “About Priority” for the system this is for.

Problem:

Details of the problem. Include lots of screenshots and instructions for how Priority can replicate the issue.

Explanation:

Why is this a problem for the customer? What impact does it have? This is to help Priority know how to prioritise the issue.

If there is nothing to add here, remove the section.

Connection Details:

Include connection details to the customer system if possible. This should be in a secure link.

Otherwise, express that we can give supervised access or that they are available on request or that it’s not possible etc. (or for Bremont, they can use Frida’s login)

If it’s not appropriate, remove the section.

Testing on up-to-date/vanilla system:

Make sure your demo system is on the latest version and bin.

If your example above is from your demo system, say so and include your help>about.

Otherwise say you can repeat in your demo system and include help>about.

If you can’t repeat in your demo system, then it will be harder for Priority to investigate.

If it is not appropriate, remove this section (i.e. there’s a problem and we don’t know what’s causing it like dump files or errors in the server log)

Required Outcome:

Say what we want Priority to do. Examples:

Please provide a fix.

Please add this to your list of future developments.

Please provide steps for how we can investigate.

Please explain what these error messages mean.

Please explain how this can be achieved.
